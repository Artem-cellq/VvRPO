## 2. UML-диаграмма

Диаграмма классов находится в файле: `UML/hotdog_uml.puml` (PlantUML).

Краткое описание иерархии:

- **Product** (abstract) — базовый класс продукта с полями `name`, `price`.
- **Component** (abstract) — компонент хот-дога, наследует `Product` (компоненты продаются отдельно).
  - `Bun` — булочка.
  - `Sausage` — сосиска.
  - `Sauce` — соус.
  - `Topping` — наполнитель.
- **HotDog** (abstract) — хот-дог, наследует `Product`, состоит из списка компонентов (композиция). Цена считается как сумма цен компонентов.
  - `HunterDog` — булочка пшеничная + охотничья сосиска + кетчуп + лук свежий.
  - `MasterDog` — булочка с кунжутом + молочная сосиска + майонез + сыр.
  - `Berlinka` — ржаная булочка + охотничья сосиска + горчица + огурец маринованный + лук красный.
- **Order** — заказ, содержит коллекцию продуктов `List<Product>` (композиция). Определяет итоговую сумму и признак «полного» заказа (заказ полный, если в нем есть хотя бы один хот-дог).
- **Main** — консольное приложение для демонстрации.

## 4. Реализация требований

| № | Требование | Как реализовано | Статус |
|---|------------|-----------------|--------|
| 1 | Иерархия классов хот-догов (HunterDog, MasterDog, Berlinka) | Абстрактный `HotDog` → три конкретных подкласса (наследование) | ✅ |
| 2 | Компоненты продаются отдельно | `Component` → `Bun/Sausage/Sauce/Topping`; заказ может содержать только компоненты | ✅ |
| 3 | Продать каждый вид хот-дога | В `Main` создан и продан каждый из трёх видов | ✅ |
| 4 | Общая сумма всех заказов | `Order.getTotal()` + сумма по всем заказам в `Main` | ✅ |
| 5 | Количество полных заказов | `Order.isFull()` (хотя бы один хот-дог) + подсчёт в `Main` | ✅ |
| 6 | Средняя стоимость заказа | Общая сумма / количество заказов в `Main` | ✅ |

Также реализованы:
- **Наследование:** `Product → Component → Bun/Sausage/Sauce/Topping`, `Product → HotDog → HunterDog/MasterDog/Berlinka`.
- **Композиция:** `Order` содержит kolekцию `Product`; `HotDog` содержит kolekцию `Component`.
- **JavaDoc:** все классы, поля, методы и конструкторы снабжены комментариями `/** ... */`.
- **Именование:** CamelCase для классов/методов/полей в соответствии с Oracle Java Code Conventions.

## 5. Результат запуска

```
=== Продажа хот-догов ===
HunterDog - 5,00 BYN [Булочка пшеничная, Сосиска охотничья, Кетчуп, Лук свежий]
MasterDog - 5,40 BYN [Булочка с кунжутом, Сосиска молочная, Майонез, Сыр]
Berlinka - 6,00 BYN [Булочка ржаная, Сосиска охотничья, Горчица, Огурец маринованный, Лук красный]

=== Все заказы ===
Заказ #1: 2 позиций, итог 5,50 BYN, полный
Заказ #2: 1 позиций, итог 5,40 BYN, полный
Заказ #3: 2 позиций, итог 8,00 BYN, полный
Заказ #4: 2 позиций, итог 2,40 BYN, неполный
Заказ #5: 2 позиции, итог 10,40 BYN, полный

Общая сумма всех заказов: 31,70 BYN
Количество полных заказов: 4
Средняя стоимость заказа: 6,34 BYN
```

Расчёт проверен вручную:
- HunterDog = 1.50+2.50+0.50+0.50 = 5.00 BYN
- MasterDog = 2.00+2.00+0.40+1.00 = 5.40 BYN
- Berlinka = 2.00+2.50+0.40+0.60+0.50 = 6.00 BYN
- Заказ 1 = 5.00+0.50 = 5.50; Заказ 2 = 5.40; Заказ 3 = 6.00+2.00 = 8.00;
  Заказ 4 = 2.00+0.40 = 2.40 (неполный, только компоненты); Заказ 5 = 5.00+5.40 = 10.40.
- Итого: 5.50+5.40+8.00+2.40+10.40 = 31.70 BYN
- Полных заказов: 4 (заказы 1, 2, 3, 5).
- Среднее: 31.70 / 5 = 6.34 BYN
